# Development

Build the C++20 engine with Windows x64 MSVC through `dev.cmd`, the one development command (`dev.cmd help`). Use `dev.cmd build [target]`, `dev.cmd check --target <target>` and `dev.cmd test -R <pattern>` from the root. Before finishing a change, run `dev.cmd check`: it builds with warnings as errors and runs the synthetic suite, which hosted CI requires. When a check fails, start from the first diagnostic and the log it names. When a test gains a game-data or GPU part, list it in `tests/test_suites.txt` (README.md "Test suites") and record the local `dev.cmd suite retail` or `vulkan` run on the pull request. For launcher changes, run `dev.cmd launcher` and `dev.cmd launcher-test`. Setup and game-data paths are in README.md.

Keep generated files in `build/` or `launcher/target/`. The one exception is the checked-in skill folders below.

Work lands through a pull request into `main`; the `landing` check must pass (README.md "Continuous integration"). Standing decisions are in `docs/DECISIONS.md`.

## Agent skills

The workflow skills are `eaw-*`: `/eaw-<name>` in Claude Code, `$eaw-<name>` in Codex. Their source is `workflow/skills/` (README there); `.claude/skills/` and `.agents/skills/` are generated by `python -I tools/skills.py generate`, so never edit them by hand. Start a piece of work with `/eaw-triage`, `/eaw-to-spec`, `/eaw-to-tickets` or `/eaw-implement`; planning starts with a preplanning record on the issue (`docs/agents/preplanning.md`); the supporting skills (`eaw-tdd`, `eaw-diagnosing-bugs`, `eaw-code-review`, `eaw-codebase-design` and others) start when the work calls for them.

### Issue tracker

GitHub Issues in `Gabriel-Barney/Empire-at-war-Vulkan`, through `gh`. See `docs/agents/issue-tracker.md`.

### Triage labels

The five default roles: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`, with `bug` and `enhancement` as categories. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: `GLOSSARY.md` at the root (created when the first term is settled), decisions in `docs/DECISIONS.md` instead of `docs/adr/`. See `docs/agents/domain.md`.
